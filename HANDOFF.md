# Project Analytics Bot — handoff / ТЗ

## Принцип работы

Бот показывает аналитику по проектам в Telegram. Он не должен менять смысл,
состав или оформление отчётов без явного запроса пользователя. Любые новые
метрики, кнопки, автоматизации и тексты добавляются только после согласования.

## Источники данных

1. **Dialog Hub** (`/opt/dialoghub/data/dialoghub.sqlite3`) — первичный
   источник по рассылкам и ответам:
   - «Отправлено» — количество первичных сообщений, отправленных в выбранный
     период;
   - «Ответили» — количество ответов на эти же сообщения, зафиксированных к
     концу выбранного периода;
   - конверсия — `Ответили / Отправлено × 100%`.
2. **TG-zayavki** — передаёт идемпотентные события в Analytics Bot:
   - `join_request` — заявка в канал;
   - `join_approved` — заявка одобрена;
   - `second_message_sent` — отправлено второе сообщение со ссылкой на канал;
   - `third_message_sent` — отправлено третье сообщение со ссылкой на сайт.
3. **Канал Маши по айфонам** — каждый пост с фотографией в привязанном канале
   считается одним лидом Маши. Username, подпись и видимый текст не являются
   условиями подсчёта.

## Формат отчёта

Для каждого проекта показываются только согласованные строки:

- Отправлено;
- Ответили и конверсия;
- Заявки в канал;
- для «ГОСЗАКУПКИ» — второе и третье сообщение;
- для «АЙФОНЫ» — лиды Маши.

Не выводить технические/дополнительные показатели без прямого запроса, включая
«всего входящих ответов», «ответили на отправки периода» и аналогичные строки.

## Отчёты и навигация

- Автоматический ежедневный отчёт — за предыдущий календарный день, после
  00:01 по Москве.
- Автоматический недельный отчёт — в понедельник за завершённую неделю.
- Автоматический месячный отчёт — первого числа за завершённый месяц.
- Если сервис был недоступен в момент отправки, отчёт должен быть безопасно
  доставлен после восстановления, без дублей.
- Кнопки по запросу сохраняются: «Вчера», «Эта неделя», «Предыдущая неделя»,
  «За всё время», «Скрипты», «По дням недели».
- «По дням недели» присылает отдельные отчёты за завершённые дни текущей недели.

## Скрипты

- «Актуальные» — только скрипты, которые отправлялись за последние два дня.
- В актуальных скриптах отображать также варианты с нулём ответов: `0/N` и
  полный текст каждого такого скрипта.
- В «Все скрипты за всё время» нулевые тексты не выводить. В конце давать
  компактную сводку: число нулевых скриптов и суммарное число отправок без
  ответов.
- Медиа/файлы не считать текстовыми скриптами.

## Надёжность и безопасность

- События TG-zayavki авторизуются заголовком `Bearer` с общим `INGEST_TOKEN`.
- Неверный токен не должен приводить к тихой потере событий: ошибку нужно
  логировать и исправлять конфигурацией, не подстановкой статистики.
- Ключи, токены, базы SQLite, виртуальные окружения и резервные копии не
  коммитить в GitHub.
- Код перед развёртыванием проверять `py_compile`; сервис после обновления
  перезапускать и проверять его статус.

## Запрет на самодеятельность

Не добавлять от себя новые метрики, формулировки, отчёты, кнопки, правила
подсчёта или изменения интерфейса. Если требование неясно либо меняет смысл
существующей аналитики, сначала запросить явное решение пользователя.
